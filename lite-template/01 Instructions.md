# AI Tutor — рабочий протокол

Читать при каждом открытии новой сессии.

Ты и пользователь развернули эту мини-методологию вместе (см. `03 Work/project_status.md` — как и когда). Дальше — правила, по которым вы работаете каждый день. Этот файл остаётся в проекте навсегда (в отличие от разовой инструкции тьютора) — так процесс подхватывается той же или любой другой сессией агента, даже если предыдущая прервалась.

## Структура

- `01 Sources/02 Description.md` — что за проект, где код, окружение.
- `02 Kanban.md` — доска задач.
- `02 Kanban notes/` — заметки к задачам, один файл на задачу.
- `03 Work/project_status.md` — текущий этап и фокус.

Нумерация файлов и папок совпадает с Pro-шаблоном (`template_new`) — при переходе на Pro не нужно ничего переименовывать: достаточно дополнить этот файл и добавить `06 Roles/`. `03 Work/` — также место для будущих рабочих документов (ТЗ, roadmap и т.п.), если проект вырастет ещё до перехода на роли.

## Колонки Kanban

- **To Do** — новые задачи.
- **In progress** — задачи в работе.
- **Check** — выполненные, ждут проверки пользователем.
- **Done** — завершённые (не читать).
- **Cancel** — отменённые; переносит туда только пользователь.

## Каждую сессию

1. Открыть `03 Work/project_status.md`.
2. Открыть `02 Kanban.md`, прочитать только `## In progress` и `## To Do` (не `## Done`/`## Cancel`).
3. **In progress** — для каждой задачи открыть файл заметки, проверить первый блок:
   - `#user` → обработать.
   - `#llm` → не выполнять задачу, а сообщить пользователю, что она ждёт его ответа или проверки (не молчать).
4. **To Do** — если в In progress не осталось задач для обработки, взять задачи из To Do в работу.
5. Если задач нет — сообщить пользователю.

## Взятие задачи в работу (из To Do)

1. Если у задачи нет файла заметки — создать `02 Kanban notes/<название задачи>.md`.
2. Если нет ссылки — заменить текст строки в `02 Kanban.md` на `[[название задачи]]`.
3. Переместить задачу из `To Do` в `In progress`.
4. Если нужен доступ к коду — открыть `01 Sources/02 Description.md`.
5. Если задача высокорисковая (удаление данных, необратимые операции, публикация вовне) — сообщить пользователю и дождаться подтверждения перед выполнением.
6. Выполнить задачу.

## Выполнение задачи

Если нужны уточнения — записать в начало файла заметки и ждать ответа, задача остаётся в `In progress`:
```
#llm
- **Дата:** ГГГГ-ММ-ДД
- **Статус:** требует уточнений

**Вопросы:**
1. ...
```

После выполнения — заменить блок на результат и переместить задачу в `Check`:
```
#llm
- **Дата:** ГГГГ-ММ-ДД
- **Файлы:** что изменено
- **Изменения:** что сделано
- **Проверка:** как проверить результат — если применимо
```

## Обработка комментария пользователя (`#user`)

`#user`-блок обрабатывается только у задач из `In progress`, всегда пишется пользователем сверху файла. После обработки — записать `#llm`-результат над ним и перенести задачу в `Check`.

## Отмена задачи

Перенести задачу в `Cancel` может только пользователь.

## Язык

Общение и заметки к задачам — на языке, зафиксированном в `01 Sources/02 Description.md`.

## Формат ссылок

Ссылки на файлы заметок — только Obsidian wiki-link: `[[название файла]]`. В названии задачи/файла не использовать `: \ / * ? " < > |` (зарезервированные символы Windows-имён файлов); вместо двоеточия — тире или скобки: `Тема — уточнение`.

## Коммиты

Коммитить только по явной просьбе пользователя. Сообщения — на языке общения, без `Co-Authored-By` и следов автогенерации без явной просьбы.

## Конвенции окружения

См. `01 Sources/02 Description.md` §«Окружение». Перед действиями, затрагивающими окружение (установка пакетов, сеть, тесты, запуск сервисов) — прочитать его.
